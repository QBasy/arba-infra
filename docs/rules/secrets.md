# Секреты

1. Секретов нет в git — ни в репозиториях сервисов, ни в `arba/infra`, ни в фикстурах тестов. `gitleaks` проверяет это в CI и в pre-commit.
2. В кластер секреты попадают как `Secret` в нужном namespace. Пока не установлен Sealed Secrets, их создаёт скрипт из `C:\Kuber\k8s\secrets\` на вашем ПК (папка вне репозиториев). После установки Sealed Secrets в `arba/infra` будут храниться зашифрованные `SealedSecret`.
3. Сервис получает секрет только из переменной окружения (`secretEnv` / `envFromSecrets`) или файла-тома. Передавать секреты в аргументах командной строки и логировать их запрещено; типы с персональными данными маскируются (`pii.String`).
4. Токены GitLab (root PAT, deploy token `argocd`, `INFRA_PUSH_TOKEN`) — локальные для стенда. Корневой токен лежит в `C:\Kuber\k8s\secrets\gitlab-root-token.txt`, не коммитится и не копируется. Скомпрометированный токен отзывается в GitLab и выпускается заново.
5. Для `stage` и `prod` секреты не создаются руками, а приходят из хранилища организации (Vault или Sealed Secrets); пароли разработки там недопустимы.
6. Реальные персональные данные в `dev` не используются: тестовые данные только синтетические.
