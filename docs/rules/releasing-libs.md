# Релиз библиотек kit и contracts и обновление сервисов

Теги не переносятся и не удаляются (см. [git.md](git.md)): Go-прокси и `go.sum` запоминают содержимое версии. Исправление всегда выходит новой патч-версией. Пустых и «пробных» тегов не создаём.

## Выпуск версии библиотеки

1. Внести изменения в ветке, открыть MR. Пока пайплайн ветки не зелёный (`gitleaks`, `lint`, `unit`, `generated-code`), тег не ставить.
2. Влить в `main` и дождаться зелёного пайплайна **на этом коммите**.
3. Для `contracts` перед этим выполнить `make gen` и закоммитить сгенерированное: проверка `generated-code` падает, если `gen/` отстаёт от `openapi/`.
4. Поставить тег на зелёный коммит `main`:

   ```bash
   git switch main && git pull
   git tag -a v0.2.4 -m "kit 0.2.4: что изменилось"
   git push origin v0.2.4
   ```

5. Дождаться зелёного пайплайна тега. Если он красный, тег остаётся как есть. Чинить дальше новой версией (`v0.2.5`), а сервисы на красную версию не переводить.

Версию выбирать так: исправление без смены API даёт патч, новое поведение даёт минор, ломающее изменение даёт мажор (`/v2`).

## Обновление сервиса на новые теги

Обновлять `go.mod` и `go.sum` нужно в одном коммите. Если поднять версию в `go.mod` без `go.sum`, у сервиса падают `go-versions` (там `go mod tidy` с `git diff --exit-code`) и `lint`.

```bash
export GOPRIVATE='*.arba.kz'
cd backend/<service>
go get gitlab.arba.kz/arba/kit@v0.2.4 gitlab.arba.kz/arba/contracts@v0.1.9
go mod tidy
git diff --stat go.mod go.sum      # меняются только строки arba/kit, arba/contracts и их зависимостей
make lint test
git add go.mod go.sum && git commit -m "chore(deps): kit v0.2.4, contracts v0.1.9"
```

Если после `go mod tidy` в `go.sum` остались старые версии `arba/kit` или `arba/contracts`, значит где-то в `go.mod` ещё указана старая версия: `grep arba go.mod`.

## Что делать с лишними тегами

Тег, который уже был опубликован, не трогаем. Если он ни в одном `go.mod` не используется, он просто остаётся в истории, а актуальной считается последняя зелёная версия. Удалять и переставлять теги можно только по решению владельца репозитория и только если никто их ещё не скачивал; в `go.sum` сервисов хеш этой версии при этом нужно будет обновить.
