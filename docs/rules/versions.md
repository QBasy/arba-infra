# Версии: что и где выкачено

Нужны два ответа: «какая версия сейчас в окружении» и «из каких версий состоит релиз платформы». Первый хранится в `arba/infra` как данные, второй — как манифест релиза. Это стандартный GitOps-подход: состояние кластера = содержимое репозитория, а история изменений = история git.

## Источник правды

Для каждого сервиса и окружения — файл `arba/infra/envs/<env>/<сервис>/app.yaml`:

```yaml
name: origination
namespace: dev
repoURL: http://gitlab.arba.kz/arba/engines/origination.git
chartPath: .helm
revision: "1a2b3c4d5e6f..."      # коммит с .helm — бот меняет
imageTag: "sha-1a2b3c4"          # тег — бот меняет
imageDigest: "sha256:9f86d0..."  # digest — бот меняет
```

В `values.yaml` рядом лежат ручные параметры окружения (реплики, хосты, ресурсы). Бот трогает только `app.yaml`, человек — только `values.yaml`. Каждое изменение — коммит `chore(dev): origination → sha-1a2b3c4`, поэтому `git log envs/dev/origination` — это история выкатов, а `git revert` — откат.

## Таблица версий

`scripts/render-versions.py` собирает из `envs/*/*/app.yaml` файл `VERSIONS.md`: окружение × сервис → версия, digest (первые 12 символов), коммит. Бот `deploy-dev` пересобирает его при каждом выкате в `dev`. Это справочник для людей; источником правды остаются `app.yaml`.

| Сервис | dev | stage | prod |
| --- | --- | --- | --- |
| `origination` | `sha-1a2b3c4` | `1.4.2` | `1.4.2` |

## Версии и SemVer

1. Версия сервиса — SemVer, повышается автоматически по Conventional Commits (см. [git.md](git.md)).
2. Версия `arba/contracts` — SemVer; ломающее изменение — только новая мажорная версия (`/v2`), старая живёт параллельно. Сервис фиксирует версию `contracts` и `kit` тегом в `go.mod`.
3. Версия чарта = версия приложения: релиз `1.4.2` выпускает чарт `1.4.2` с `appVersion: 1.4.2`.
4. Схема БД меняется только обратно совместимо (expand → migrate → contract), поэтому предыдущая версия сервиса всегда работает с новой схемой — откат возможен без отката БД.

## Манифест релиза платформы

Когда набор готов к поставке (стенд банку, пилот), в `arba/infra/releases/` добавляется файл `v<ГГГГ.ММ.N>.yaml`:

```yaml
release: v2026.10.1
date: 2026-10-20
components:
  origination: { version: 1.4.2, digest: sha256:9f86d0..., chart: 1.4.2 }
  scoring:     { version: 2.0.1, digest: sha256:a1b2c3..., chart: 2.0.1 }
  contracts:   { version: 1.8.0 }
```

Он фиксирует, какие версии проверены вместе, и из него собирается umbrella-чарт для on-premise (NFR-11). Манифест создаётся MR и содержит только тестированные сочетания.

## Продвижение между окружениями

`dev` обновляется автоматически с каждым merge в `main`. `stage` и `prod` — только через MR в `arba/infra`, в котором меняются те же три поля из `dev` (тег, digest, ревизия) на релизные значения. Образ не пересобирается: в `stage` и `prod` едет тот же digest, который проверили в `dev`.

## Откат

Откат — `git revert` коммита в `arba/infra` и merge; Argo CD вернёт прежний digest. Для `dev` можно откатить и вручную через интерфейс Argo CD, но это временно: self-heal вернёт состояние из git, поэтому реальный откат всегда коммитом.
