# Правила разработки Arba

Это сводка правил для всех, кто пишет код и выкатывает его в локальный кластер. Источник правды по продукту — документ «Arba — подготовка к разработке»; здесь — как это работает на практике. Правило, которое можно проверить машиной, проверяет CI. Исключения — только через ADR в `arba/docs`.

## Главные принципы

1. **Кластер меняется только коммитом.** Никакого `kubectl apply` и `helm install` руками. Единственный путь — merge в `arba/infra` (или бот CI для `dev`), дальше Argo CD.
2. **Собираем один раз, переносим по digest.** Образ собирается на коммит в `main`; в `stage` и `prod` едет тот же `sha256`, а не пересобранный.
3. **Каждый бэкенд-репозиторий содержит `.helm/`.** Чарт живёт рядом с кодом и версионируется вместе с ним. Параметры окружений — в `arba/infra`.
4. **Всё локально.** Образы, чарты, исходники и деплой — из GitLab и registry внутри кластера. Внешние сервисы нужны только для скачивания базовых образов и Go-модулей (см. «Что пока зависит от интернета»).
5. **Движки не открываются наружу сами.** Публичный вход — `platform/gateway` и `platform/web`. Ingress у движка — только временно для отладки в `dev`.

## Где что живёт

| Что | Где |
| --- | --- |
| Код сервиса, `Dockerfile`, `.helm/`, `.gitlab-ci.yml` | репозиторий сервиса, `arba/engines/<имя>` или `arba/platform/<имя>` |
| Общие CI-шаблоны | `arba/infra` → `ci-templates/` |
| Шаблоны репозитория (`.helm`, Dockerfile, Makefile) | `arba/infra` → `templates/` |
| Что выкачено в каждом окружении | `arba/infra` → `envs/<env>/<сервис>/` |
| Argo CD (проект, ApplicationSet) | `arba/infra` → `argocd/` |
| Namespace, квоты, сетевые политики | `arba/infra` → `namespaces/` |
| Конфиг kind и манифесты платформы | `arba/infra` → `kind/`, `platform/` |
| Манифесты релизов платформы | `arba/infra` → `releases/` |
| ADR и глоссарий | `arba/docs` |

## Адреса локального стенда

| Что | Адрес |
| --- | --- |
| GitLab | `http://gitlab.arba.kz` |
| Argo CD | `http://argocd.arba.kz` |
| Registry | `registry.arba.kz` (образы `registry.arba.kz/arba/...`) |
| Приложения в `dev` | `<сервис>.dev.arba.kz`, например `api.dev.arba.kz`, `app.dev.arba.kz`, `auth.dev.arba.kz` |
| Инструменты | `grafana.arba.kz` и другие, по одному имени на инструмент |
| Каталог всего, что опубликовано | `http://arba.kz/` |

Wildcard-DNS для `*.arba.kz` обслуживает локальный DNS-контейнер; правило Windows уже настроено скриптом `11-windows-dns.ps1`.

## Что пока зависит от интернета

Честный список, чтобы не обманываться словом «локально»: базовые образы и образы утилит CI скачиваются через зеркала в кластере (кэш наполняется при первом скачивании, дальше работает офлайн); модули Go берутся с `proxy.golang.org`; базы сканеров (`trivy`, `govulncheck`) обновляются из сети. Для полной автономности (NFR-11) нужен свой Go-прокси (Athens) и зеркало баз сканеров — это отдельная задача, пока не сделана.

## Открытые решения

| Вопрос | Принято сейчас | Когда пересмотреть |
| --- | --- | --- |
| Сборщик образов | Kaniko в runner'е (не нужен Docker и привилегии) | при смене на rootless BuildKit меняется только шаблон CI |
| Источник чарта для Argo CD | `.helm/` из git-репозитория сервиса по SHA | для поставки банку чарт дополнительно публикуется как OCI-артефакт |
| Ingress | ingress-nginx | если банку нужен Gateway API / Envoy — см. [ingress.md](ingress.md) |
| TLS | http локально | вместе с локальным CA (mkcert или cert-manager) |
| Секреты | Secret'ы создаются вручную скриптом, в git не попадают | Sealed Secrets, когда поставим |
| Namespace'ы | один `dev` для всего Arba | `stage`/`prod` — отдельные namespace'ы или кластеры |
